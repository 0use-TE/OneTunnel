# 一隧第一版：由用户执行的测试清单

## 0.3.13 Tailscale 本机端口转发

- 覆盖安装后旧连接默认没有转发端口，节点身份和订阅保留；不会为全部历史节点自动开放 SSH。
- 点击已添加的 Tailscale → 本机端口转发 → 添加端口，入站和本机均为 8022，点完成。总 VPN 停止时只保存；运行中应自动重载，不重建 Android TUN。端口修改后节点 IP 应保持不变，已有会话会重连。
- 启用该连接及总 VPN，在 Termux 执行 `whoami` 确认用户名，启动 `sshd` 并确认服务监听 127.0.0.1 或 0.0.0.0 的 8022。其他 Tailnet 设备执行 `ssh -p 8022 <用户名>@<OneTunnel 节点 IP>`，验证握手、登录与双向交互。不要误用官方 Tailscale App 的另一节点 IP；ACL/Grants 需允许访问配置的端口。
- 可改成入站 2222 → 本机 8022，远端 SSH 改用 `-p 2222`；原 8022 不再开放。重复、空白、非整数、超范围和超过 16 条应被拒绝，且不会覆盖上次有效配置。
- 删除转发条目并完成、关闭该 Tailscale、删除连接或停止总 VPN 后，新请求应无法访问旧端口，已有 SSH 会话断开。重新启用后恢复保存的转发，保留节点身份。单独浏览器认证不会开放本机端口。
- 本版仅构建 APK；宿主 TCP 双向传输、半关闭及清理已由自动测试覆盖，真实 Tailnet/ACL/Termux SSH 登录仍需上述设备验证。

## 0.3.12 规则点击与长按拖拽

- 点按规则的文字或其周围空白，按压反馈应覆盖有内边距的整张圆角区域，边框与文字保持间距，右侧删除按钮独立操作；浅色与深色都应清楚。
- 规则 → 排序：短按滑动正常滚动；长按任意普通规则后整行浮起，上下拖动调整位置，松手放下。靠近顶部/底部并停留时列表持续自动滚动，可跨多个屏幕移动；第一条、最后一条普通规则和重复内容均可操作，列表不应跳回顶部。
- MATCH 单独固定在底部，没有拖拽手柄，不能被拖起或被普通规则越过。“取消”或返回不保存本次弹窗内的排序；“完成”一次保存全部调整，VPN 运行中仍按原热重载逻辑应用。
- 本版只提供 APK 供手动覆盖安装，未向用户设备安装；长按触摸与边缘滚动尚待设备验证。本地模拟器缺少系统镜像，不能将逻辑测试通过视为实机验证。

## 0.3.7 运行中添加、在线设备与免认证

- 启动统一连接后，“添加连接”里的 WG 文件 / 相机扫码 / 图片二维码、Tailscale、Clash 文件 / 订阅入口均可使用。确认添加自动保存并热重载，Android VPN 不重建；已有连接可能短暂重连，完成后新节点应参与规则分流。规则 / 监听 / 高级 YAML 设置仍需停止后修改。
- 打开文件选择器再返回应用后确认导入，不能因 IPC 尚未重新绑定就立即停掉 VPN；重载期间显示“正在应用”，禁用重复添加 / 切换。新订阅可只缓存，也可当场设为当前配置；当前 Clash 仍只有一份。
- 打开 Tailscale 编辑窗口，在线设备标题显示数量，默认不展开设备明细；点击展开，再点击收起，轮询状态不反复展开。
- 开启 HTTP / 局域网后显示“添加账号”开关：默认保留认证，关闭则隐藏账号密码字段并免认证；重新打开恢复原有认证设置。免认证仍保留私网来源限制，不开启外部控制 API。

## 0.3.6 HTTP 代理端口

- 设置 → HTTP 代理：开关、HTTP 监听端口、允许局域网连接。默认关闭，端口 7890；端口在代理关闭时也能预先设置，有效输入自动保存，重开页面应保留。输入非数字或 1024–65535 之外的值应报错且不覆盖已存端口。
- 开启 HTTP 代理、关闭局域网共享，启动统一连接后本机使用 `127.0.0.1:端口`；从其他设备应无法连接。开启共享后才监听局域网，需要认证，展示本机 Wi-Fi / 以太网地址。关闭 HTTP 总开关后应无代理监听，保留端口与共享偏好。
- 已有 LAN 共享配置不应因更新被关闭、更换端口或丢失认证信息；切换订阅保留 HTTP / LAN 设置。修改端口前停止统一连接，下次连接生效。
- 设置页配置区只有导入与高级配置两个入口，示例与直连测试模板仅在高级配置中。

## 0.3.5 连接编辑、删除与认证

- 连接卡片的空白区域和文字区域均可打开编辑，按压反馈覆盖整张圆角卡片；右侧开关不打开编辑。
- 编辑订阅 / WG / TS 可以点击“删除连接”；取消删除保持配置和缓存不变。删除 WG/TS 后列表条目消失，原规则的出口为 REJECT；删除最后一条仍应保留有效配置。删除当前订阅保留独立本机连接、国内直连偏好和 LAN 设置；其他流量若原来使用该订阅，应变为阻止。
- Tailscale 点击“浏览器认证”应打开系统浏览器，完成认证后回到 OneTunnel；延迟到达的认证链接也应自动打开，普通状态刷新不重复打开。已启动统一 VPN 时认证按钮仍可使用（该 TS 连接需已启用）。首次账号登录和批准由用户完成。
- 删除条目不自动在 Tailscale 管理后台吊销设备，后台设备管理仍由账户所有者操作。

## 0.3 界面使用变化

- 已更名 OneTunnel。连接页总开关启动/停止统一 VPN；每条订阅、WG、TS 用独立开关。订阅一次最多启用一份，WG/TS 可同时启用多个。
- 图形操作与确认导入后自动保存，不再有“未保存”或保存按钮；以下历史步骤中的“保存”由程序自动完成。高级 YAML 只自动保存检查通过的内容。
- 运行中切换连接会重载出站并断开已有连接，测试应用重连；失败应停止 VPN。关闭的出口保留规则但返回拒绝，不自动改走直连。
- WG 按网段分流时，导入/启用新增重叠应弹窗列出具体连接与网段，取消不改变配置；继续则按原规则顺序。测试 IPv4 包含、完全相同、IPv6、互不相交、已关闭连接与仅添加出口。
- 检查更新安装后原订阅与配置仍在；退出重开后开关状态保留。开发者未使用真实账号/VPN 执行本轮出口联网测试。

## 0. 先准备恢复方式

- 保留原 Clash App、订阅和配置，不卸载、不清数据。
- 记住怎样打开原 Clash 并重新启动 VPN；若系统开启了“始终开启 VPN/无 VPN 时阻止连接”，先了解其效果，不要盲目修改。
- 在不影响工作、远程连接、支付或下载的时候测试。
- 不在聊天里发送 WG 私钥、Tailscale auth-key、订阅链接或完整 YAML。

## 1. 安装但不启动 VPN

- 手动安装交付的 ARM64 APK，应用名为“一隧 · Mihomo”。这是 debug/alpha 构建，不是生产版本。
- 打开连接页，应显示“未连接”，不应自动出现系统 VPN 授权请求。
- 原 Clash 应继续运行；首页显示的出站数量只是配置统计，不能当作连通。
- 设置与高级配置页会禁止截图，这是为了避免泄露密钥；连接与规则页可截图。
- 在设置中分别选择跟随系统、浅色、深色，检查文字、开关和系统状态栏；退出重开后主题应保留。

## 2. 配置准备（仍不切换 VPN）

- 用文件选择器导入自己已有的 Mihomo YAML；导入只进入编辑器，不自动下载订阅或读取其他 App 私有数据。
- 或加载“三出口示例”，填写真实公网节点、WG 和 Tailscale 参数，替换全部占位符。
- WG 的 address/private-key/public-key/endpoint/allowed-ips 必须与真实配置匹配；例子里的 10.77.0.0/24 是演示网段。
- Tailscale 可用浏览器登录或高级配置中的 auth-key；本 App 注册新节点，不复用原 Tailscale App。浏览器登录步骤见下。
- 把 WG、tailnet 子网、Wi-Fi 网段重叠问题提前处理好；Tailscale 网段不只有 100.64.0.0/10。
- 给 MagicDNS/内部域名配置相应 nameserver-policy。
- 明确最终 MATCH 出口。程序不自动添加 DIRECT 回退；不要为了测试把所有出口都设置成 DIRECT。
- 点“离线检查”，再点“加密保存”。离线检查不等于验证密钥、服务器、订阅、ACL 或所有核心配置选项。
- 配置里的本地入站端口、external-controller、profile tun、其他 listeners 等会被覆盖；设置页显式开启的代理监听、Tailscale 编辑页显式添加的节点 TCP 转发是例外。第一版不支持 PROCESS-* 规则。
- 规则页切换国内直连、选择 MATCH 出口，添加域名和网段规则，确认顺序正确；保存并重新连接才应用。新模板默认国内直连，导入保留原规则。国内数据库首次可能需要下载。

## 2a. 局域网共享（连通后由用户验证）

- 设置中开启允许局域网连接，默认生成随机认证密码；可修改端口/认证信息，点击应用后再保存配置。
- 启动 VPN，在同一 Wi-Fi 的另一台设备上手动设置本机显示的 IP、端口、用户名和密码。分别测试 HTTP 与 SOCKS5。
- 不提供认证或使用错误密码应失败；来自公网的连接不应被允许。核心控制接口仍不应开放。
- 关闭 VPN 后端口应关闭。关闭局域网开关、保存并重新连接后不应继续监听。

## 2b. WireGuard 文件与二维码导入

- 连接页选择 `.conf` 文件、相机扫码或从图片识别；取消选择 / 拒绝相机权限后原有配置不应变化。无相机时可用文件或图片。
- 扫描页与预览禁止截图；二维码内容不应出现在日志、Intent 结果或磁盘临时文件中。
- 导入预览确认名称、地址、Peer 数与路由方式。普通内网 AllowedIPs 可添加到国内规则和 MATCH 之前；含 `0.0.0.0/0` 或 `::/0` 时仅允许选择添加出口或显式改 MATCH。
- 核对多 Peer、IPv6 Endpoint、预共享密钥；脚本 / 不支持字段应失败而非忽略。DNS 搜索域、ListenPort / Table / SaveConfig 等差异在预览提示。
- 添加后需点保存，才会替换已保存配置；不会自动启动 VPN。已有 WG / TS / 普通节点和自定义规则不应被替换。
- 相机需测试对焦、旋转、权限取消；图片需测试普通 / 旋转 / 反色二维码、非二维码图片与过大文件。保存后由用户验证真实 WG TCP/UDP 和 DNS。

## 2c. 订阅链接

- 在“添加连接”选择订阅，分别添加 Ouse 与魔戒的链接和名称；两者应同时保留在列表。查看预览中的节点、分组、规则数量和兼容提示后应用并保存。
- 手动更新、切换缓存：停止时可应用，运行时只能更新缓存；不应自动切换正在工作的 VPN。保存后退出重开应能看到订阅列表。
- 更新时检查保留当前规则的选项；切换后本地添加的 WG/TS 和局域网设置应仍存在。规则引用不存在的组应明确报错。
- 测试失效链接、断网、取消，不应暴露完整链接、正文或覆盖已保存配置。节点名称中的 emoji 应保持完整。实际节点连接需要另行启动 VPN 验证。

## 2d. Tailscale 浏览器登录

- 添加 Tailscale 节点并保存，保持统一 VPN 停止。点击登录应进入认证状态并打开系统浏览器，不申请 VPN、不替换原 Clash。
- 在真实官方或已配置的 Headscale 登录页完成认证，返回应用查看地址与设备；认证完成后服务应自动结束。之后手动启动统一 VPN，核对后台只有同一个新节点身份。
- 测试浏览器取消、返回后重试、认证通知停止、后台等待与认证超时；认证失败不应自动建立统一 VPN。
- 再次启动、重启应用后身份应保留；MagicDNS、ACL、子网路由与设备联网仍需下面的出口测试。

## 3. 主动切换（此时可能失联）

- 确认你能恢复原 Clash，再点“手动启动统一 VPN”。
- 阅读切换警告，自己确认系统 VPN 权限。
- 系统通知与首页应显示核心/TUN 状态；即使显示“运行”，也只是核心启动成功，不代表各出口连通。
- 若启动失败，不要反复自动切换。先停止本 App，手动恢复原 Clash，记录泛化错误和配置类型。

## 4. 分出口测试

每项独立记录成功/失败，避免把代理可用误认为三种出口都可用：

| 项目 | 由你准备的目标 | 要验证的内容 |
|---|---|---|
| 公网代理 | 你已知需要代理的网站 | 指定代理节点能连接；不是意外直连 |
| WG TCP | 内网 HTTP/SSH/NAS 地址 | 目标网段确实走 WG |
| WG UDP | 已有内网 UDP 服务 | 双向 UDP 和保持连接 |
| Tailnet TCP | 另一台 tailnet 设备的已知 TCP 服务 | 新节点已登录、ACL 允许、目标可达 |
| Tailnet UDP | tailnet 内已有 UDP 服务 | UDP 路径有效，不只 TCP |
| MagicDNS | 真实的 tailnet 域名 | 指定 DNS 策略解析并能连接 |
| Tailscale 子网 | 已批准发布的子网地址 | accept-routes、路由审批、ACL、Mihomo 规则同时生效 |
| IPv6 | 已知 IPv6 服务 | 无绕过/意外泄漏；不需要时明确阻断 |

ping 不是本版所有出站能力的充分判据，不能用 ping 失败直接等同于 TCP/UDP 失败，也不能反过来。

## 5. 稳定性和故障（初步连通后再做）

- Wi-Fi 与移动网络切换、锁屏、亮屏和后台一段时间。
- WG endpoint 无法连接、Tailscale 节点不可用、DNS 超时等情形下，检查目标是否按预期失败，而不是落到意外的 DIRECT。
- 同一连接不能保证切换出口无损重连。
- 停止按钮/通知停止应结束服务，不自动重启。
- 本版没有配置系统级 always-on/lockdown，VPN 进程停止后普通网络可能恢复，不是全局 kill switch。

## 6. 恢复

1. 在本 App 或其通知里停止 VPN；必要时在系统 VPN 设置断开本 App。
2. 手动打开原 Clash，启用原来的配置/VPN。
3. 确认原先的联网方式恢复，再回来反馈。

反馈只需：应用版本、安卓版本、出错阶段、WG/TS/代理哪一条路径失败、是否涉及 DNS/UDP/IPv6，以及不含凭据的状态提示。不要外发完整配置、状态目录或认证链接。
