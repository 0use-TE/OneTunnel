# 一隧第一版：由用户执行的测试清单

> **AI 没有安装、启动本 App 或接管 VPN。以下都是待你执行的测试，不是已通过项目。**
>
> Android 对同一用户只能有一个活跃 VPN。确认启动本 App 后，原 Clash/WireGuard/Tailscale VPN 会被替换，GPT 可能立即失联。请先把本清单保存到本地，别依赖在线对话指导恢复。

## 0. 先准备恢复方式

- 保留原 Clash App、订阅和配置，不卸载、不清数据。
- 记住怎样打开原 Clash 并重新启动 VPN；若系统开启了“始终开启 VPN/无 VPN 时阻止连接”，先了解其效果，不要盲目修改。
- 在不影响工作、远程连接、支付或下载的时候测试。
- 不在聊天里发送 WG 私钥、Tailscale auth-key、订阅链接或完整 YAML。

## 1. 安装但不启动 VPN

- 手动安装交付的 ARM64 APK，应用名为“一隧 · Mihomo”。这是 debug/alpha 构建，不是生产版本。
- 打开首页，应显示“未启动”，不应自动出现系统 VPN 授权请求。
- 原 Clash 应继续运行；首页显示的出站数量只是配置统计，不能当作连通。
- 进入“配置”页会禁止截图，这是为了避免泄露密钥；首页和说明页可截图。

## 2. 配置准备（仍不切换 VPN）

- 用文件选择器导入自己已有的 Mihomo YAML；导入只进入编辑器，不自动下载订阅或读取其他 App 私有数据。
- 或加载“三出口示例”，填写真实公网节点、WG 和 Tailscale 参数，替换全部占位符。
- WG 的 address/private-key/public-key/endpoint/allowed-ips 必须与真实配置匹配；例子里的 10.77.0.0/24 是演示网段。
- Tailscale 第一次推荐使用你自己生成的 auth-key。不要把示例字符串当成有效密钥；本 App 会注册新节点，不会复用原 Tailscale App。
- 把 WG、tailnet 子网、Wi-Fi 网段重叠问题提前处理好；Tailscale 网段不只有 100.64.0.0/10。
- 给 MagicDNS/内部域名配置相应 nameserver-policy。
- 明确最终 MATCH 出口。程序不自动添加 DIRECT 回退；不要为了测试把所有出口都设置成 DIRECT。
- 点“离线检查”，再点“加密保存”。离线检查不等于验证密钥、服务器、订阅、ACL 或所有核心配置选项。
- 配置里的本地入站端口、external-controller、profile tun、其他 listeners 等会被安全覆盖；第一版不支持 PROCESS-* 规则。

## 3. 主动切换（此时可能失联）

- 确认你能恢复原 Clash，再点“手动启动统一 VPN”。
- 阅读切换警告，自己确认系统 VPN 权限。
- 系统通知与首页应显示核心/TUN 状态；即使显示“运行”，也只是核心启动成功，不代表各出口连通。
- 若启动失败，不要反复自动切换。先停止本 App，手动恢复原 Clash，记录泛化错误和配置类型。

## 4. 分出口测试

每项独立记录成功/失败，避免把代理可用误认为三种出口都可用：

| 项目 | 由你准备的目标 | 要验证的内容 |
|---|---|---|
| 公网代理 | 你已知需要代理的网站 | 指定代理节点能连接；不是意外直连 |
| WG TCP | 内网 HTTP/SSH/NAS 地址 | 目标网段确实走 WG |
| WG UDP | 已有内网 UDP 服务 | 双向 UDP 和保持连接 |
| Tailnet TCP | 另一台 tailnet 设备的已知 TCP 服务 | 新节点已登录、ACL 允许、目标可达 |
| Tailnet UDP | tailnet 内已有 UDP 服务 | UDP 路径有效，不只 TCP |
| MagicDNS | 真实的 tailnet 域名 | 指定 DNS 策略解析并能连接 |
| Tailscale 子网 | 已批准发布的子网地址 | accept-routes、路由审批、ACL、Mihomo 规则同时生效 |
| IPv6 | 已知 IPv6 服务 | 无绕过/意外泄漏；不需要时明确阻断 |

ping 不是本版所有出站能力的充分判据，不能用 ping 失败直接等同于 TCP/UDP 失败，也不能反过来。

## 5. 稳定性和故障（初步连通后再做）

- Wi-Fi 与移动网络切换、锁屏、亮屏和后台一段时间。
- WG endpoint 无法连接、Tailscale 节点不可用、DNS 超时等情形下，检查目标是否按预期失败，而不是落到意外的 DIRECT。
- 同一连接不能保证切换出口无损重连。
- 停止按钮/通知停止应结束服务，不自动重启。
- 本版没有配置系统级 always-on/lockdown，VPN 进程停止后普通网络可能恢复，不是全局 kill switch。

## 6. 恢复

1. 在本 App 或其通知里停止 VPN；必要时在系统 VPN 设置断开本 App。
2. 手动打开原 Clash，启用原来的配置/VPN。
3. 确认原先的联网方式恢复，再回来反馈。

反馈只需：应用版本、安卓版本、出错阶段、WG/TS/代理哪一条路径失败、是否涉及 DNS/UDP/IPv6，以及不含凭据的状态提示。不要外发完整配置、状态目录或认证链接。
